# Repositorio y publicación

- Repositorio único: `otromas1234/material-asignaturas`; rama operativa fija: `main`. Verifica acceso y árbol reales; no presupongas capacidades MCP por este documento.
- Entrada: `asignaturas/<slug>/examenes-referencia/` en un tag exacto e inmutable seleccionado. Con plan, conserva exactamente su `source_snapshot`; sin plan, verifica el snapshot material vigente pertinente. Convención: `plan/<slug>/<YYYYMMDD>-<identificador-corto>`. Enumerar tags, resolverlos a commits y verificar pertinencia; ni orden lexicográfico ni head de rama sustituyen esa resolución. Ausencia, conflicto o ambigüedad bloquean.
- `source_snapshot` tiene solo `repository` y `tag`. La rama nunca forma parte de ese objeto. Las referencias pertenecen a la asignatura inequívoca, sin traversal, rutas absolutas ni transferencias externas.
- Única salida remota: `examenes/<slug>/context-exam.md`. No escribir materiales, planes, prácticas ni otro perfil. Publicar perfil no crea snapshot material. Nunca crear, mover ni borrar tags.
- Analizar/actualizar autoriza el commit si destino y alcance son inequívocos. Comprueba lectura/escritura, revisión previa y capacidad de commit atómico antes de escribir. Relee contenido en el SHA completo devuelto, no en head; informa `published` solo tras igualdad de contenido y ruta.
- Usa operaciones GitHub realmente instaladas. `publish_profile` es un adaptador inyectable para simulación, no un cliente GitHub ni garantía de permisos. Su contrato `commit(repository, branch, files, expected_head=...)` exige comparación atómica contra revisión anterior; un chequeo de head separado no sustituye ese control. `head` y `read(repository,path,sha)` son capacidades abstractas, no nombres de herramientas MCP.
- Conflicto: detenerse y releer. Fallo previo a commit: `unpublished`, sin SHA. Fallo posterior: comunicar SHA conocido y verificación pendiente; reconciliar por SHA antes de reintentar. Nunca repetir carga ciegamente ni borrar para recuperar. Conservar historial ordinario y revisión anterior.
- Pruebas exclusivamente sintéticas, offline y con mocks. No ejecutar escrituras GitHub ni operaciones de tags desde tests.
